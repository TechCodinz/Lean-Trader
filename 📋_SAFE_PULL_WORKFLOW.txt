📋 SAFE WORKFLOW: Check VPS → Backup → Compare → Pull
════════════════════════════════════════════════════════════════════════════════

This ensures you NEVER lose VPS-only changes that previous agents made!

════════════════════════════════════════════════════════════════════════════════
🔍 STEP 1: CHECK CURRENT VPS STATE
════════════════════════════════════════════════════════════════════════════════

cd ~/apex_bot

# See what's running:
ps aux | grep python | grep -v grep

# See current branch:
git branch --show-current

# See recent activity:
tail -30 apex.log

# Check database:
sqlite3 evolution_engine.db "SELECT COUNT(*), MAX(generation) FROM model_evolution;"

════════════════════════════════════════════════════════════════════════════════
🔄 STEP 2: FETCH LATEST (Don't pull yet!)
════════════════════════════════════════════════════════════════════════════════

# This downloads branch info without changing your files
git fetch origin continue-from-micro-fix

════════════════════════════════════════════════════════════════════════════════
🔍 STEP 3: COMPARE VPS vs BRANCH
════════════════════════════════════════════════════════════════════════════════

bash 🔍_COMPARE_VPS_VS_BRANCH.sh

This shows:
✅ Commits you're behind/ahead
✅ Files different on VPS vs branch
✅ What will change when you pull
✅ If there will be conflicts

════════════════════════════════════════════════════════════════════════════════
💾 STEP 4: BACKUP CURRENT VPS STATE
════════════════════════════════════════════════════════════════════════════════

bash 💾_BACKUP_VPS_BEFORE_PULL.sh

This creates a timestamped backup with:
✅ All core Python files
✅ Evolution database
✅ Log files
✅ Modified files (VPS-only changes)
✅ Untracked files
✅ Patch of all differences
✅ Complete state snapshot

────────────────────────────────────────────────────────────────────────────────
IMPORTANT: Review the backup!
────────────────────────────────────────────────────────────────────────────────

After backup completes, check these files:

# See what was backed up:
ls -lh VPS_BACKUP_*/

# Review your VPS-only changes:
cat VPS_BACKUP_*/vps_changes.patch

# Review state snapshot:
cat VPS_BACKUP_*/VPS_STATE.txt

# Check which files differ:
cat VPS_BACKUP_*/diff_files.txt

════════════════════════════════════════════════════════════════════════════════
📥 STEP 5: PULL NEW CHANGES (Now it's safe!)
════════════════════════════════════════════════════════════════════════════════

# Standard pull:
git pull origin continue-from-micro-fix

# Or if you have uncommitted changes you want to keep:
git stash                                    # Save your changes
git pull origin continue-from-micro-fix      # Pull new changes
git stash pop                                # Re-apply your changes

# Or if you want to overwrite everything with branch version:
git fetch origin continue-from-micro-fix
git reset --soft origin/continue-from-micro-fix   # Keeps your changes as uncommitted
# Review changes, then decide to keep or discard

════════════════════════════════════════════════════════════════════════════════
✅ STEP 6: VERIFY AFTER PULL
════════════════════════════════════════════════════════════════════════════════

# Check you got the new files:
ls -lh WEBSOCKET_DATA_FEED.py SMART_ORDER_MANAGER.py SMART_TRADE_FILTER.py SIGNAL_AGGREGATOR.py DYNAMIC_POSITION_SIZER.py

# Verify database still intact:
sqlite3 evolution_engine.db "SELECT COUNT(*), MAX(generation) FROM model_evolution;"

# Check recent commits:
git log --oneline -3

════════════════════════════════════════════════════════════════════════════════
🔄 STEP 7: RESTORE VPS CHANGES (If needed)
════════════════════════════════════════════════════════════════════════════════

If you had VPS-only changes that got overwritten, restore them:

# See what changed:
cat VPS_BACKUP_*/vps_changes.patch

# Apply your old changes on top of new code:
cd ~/apex_bot
git apply VPS_BACKUP_*/vps_changes.patch

# Or manually restore specific files:
cp VPS_BACKUP_*/modified_files/SOME_FILE.py ./

════════════════════════════════════════════════════════════════════════════════
💡 COMMON SCENARIOS
════════════════════════════════════════════════════════════════════════════════

SCENARIO 1: "No changes on VPS"
────────────────────────────────────────────────────────────────────────────────
If comparison shows no differences:
→ Safe to pull directly
→ git pull origin continue-from-micro-fix

────────────────────────────────────────────────────────────────────────────────
SCENARIO 2: "VPS has modified files"
────────────────────────────────────────────────────────────────────────────────
If you have uncommitted changes:
→ Backup first
→ Review vps_changes.patch to see what you changed
→ Decide: keep VPS changes or use branch version
→ Use git stash if you want to keep your changes

────────────────────────────────────────────────────────────────────────────────
SCENARIO 3: "Pull causes conflicts"
────────────────────────────────────────────────────────────────────────────────
If git pull fails with conflicts:
→ git merge --abort (cancel the merge)
→ Review backup to see your changes
→ Manually merge: keep your critical changes, add new optimizations

────────────────────────────────────────────────────────────────────────────────
SCENARIO 4: "Database got replaced"
────────────────────────────────────────────────────────────────────────────────
If database is reset after pull:
→ cp VPS_BACKUP_*/evolution_engine.db ./
→ Restores your Generation 1020+ data

════════════════════════════════════════════════════════════════════════════════
⚠️  IMPORTANT NOTES
════════════════════════════════════════════════════════════════════════════════

1. ALWAYS backup before pulling
2. ALWAYS compare before pulling
3. Review vps_changes.patch - it shows what previous agents did on VPS
4. Database backups are in VPS_BACKUP_* folders
5. Keep backups until you verify new setup works
6. If in doubt, DON'T pull yet - ask for help!
